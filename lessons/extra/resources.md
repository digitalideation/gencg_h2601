# Tools & Resources

This page collects tools, references, tutorials, artists, examples and other material that may be useful throughout the module.

**You are not expected to work through everything on this page.**

Use it as a reference when you need technical help, want to investigate a subject more deeply, or are looking for creative inspiration.

Some links have been part of this course for many years. Older resources are kept when they still contain useful ideas, even if the technology or platform around them has changed.

## Core tools

These are the main tools we will use during the semester.

### p5.js

[p5.js](https://p5js.org/) is our main creative coding framework. It is built on JavaScript and provides an accessible API for drawing, animation, interaction, images, sound and other browser-based experiments.

- [p5.js](https://p5js.org/)
- [Getting started with p5.js](https://p5js.org/get-started/)
- [p5.js Learn](https://p5js.org/learn/)
- [p5.js Reference](https://p5js.org/reference/)
- [p5.js Web Editor](https://editor.p5js.org/)
- [p5.js Wiki](https://github.com/processing/p5.js/wiki/)
- [p5.js demos](https://p5-demos.glitch.me/)
- [Introduction to Programming for the Visual Arts with p5.js - Kadenze](https://www.kadenze.com/courses/introduction-to-programming-for-the-visual-arts-with-p5-js/info)

### VS Code

We use VS Code as our local development environment.

- [Visual Studio Code](https://code.visualstudio.com/)
- [p5.vscode extension](https://marketplace.visualstudio.com/items?itemName=samplavigne.p5-vscode)
- [Live Server extension](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer)

VS Code is also where you can inspect your project files, use Git, commit changes and push them to GitHub.

### Git & GitHub

We use Git to keep a history of our work and GitHub to store and share repositories.

- [Git](https://git-scm.com/)
- [GitHub](https://github.com/)
- [GitHub Docs](https://docs.github.com/)

Do not worry about learning every Git command. We will use a small practical subset during the course.

### Obsidian

Your personal course repository will also function as an Obsidian vault.

Use Obsidian for:

- weekly process notes
- references
- images
- screenshots
- short reflections
- links between ideas
- embedded Excalidraw sketches

Resources:

- [Obsidian](https://obsidian.md/)
- [Obsidian overview on Wikipedia](https://en.wikipedia.org/wiki/Obsidian)

### Excalidraw

Use Excalidraw inside Obsidian for fast visual thinking.

Typical uses include:

- diagrams
- layouts
- arrows
- system maps
- parameter sketches
- algorithm ideas
- pipeline diagrams
- annotations
- rough visual experiments

The drawings do not need to be polished.

- [Obsidian Excalidraw plugin](https://github.com/zsviczian/obsidian-excalidraw-plugin)
- [Excalidraw](https://excalidraw.com/)

## Generative AI & Media

Later in the semester we will connect our own code with generative media systems.

### Replicate

Replicate provides API access to many generative models and gives us a relatively consistent way of experimenting with different media.

- [Replicate](https://replicate.com/)
- [Replicate documentation](https://replicate.com/docs)
- [Explore models on Replicate](https://replicate.com/explore)

We may use models for:

- image generation
- image transformation
- image-to-video
- video generation
- sound and audio
- multimodal experiments

The course is not tied to one particular model. Models and platforms change quickly. Focus on understanding the **input → process → output** relationship and what each stage contributes to your system.

## Galleries & Inspiration

Sometimes the best way to learn is simply to look at a lot of work.

- [fyprocessing](https://fyprocessing.tumblr.com/)
- [Class Pinterest collection](https://www.pinterest.ch/9uill0m/generative-class/)
- [Gallery of experiments](http://csh.bz/)
- [30000fps](https://30000fps.com/)
- [Artnome](https://artnome.com)

When looking at work, try not to ask only:

> How can I reproduce this effect?

Also ask:

- What might the rules be?
- What is fixed?
- What is variable?
- Where does randomness enter?
- What changes over time?
- What would happen if one rule changed?
- What makes this system interesting rather than merely visually attractive?

## Open source, borrowing and attribution

Creative coding has a long culture of:

- sharing code
- learning from examples
- using libraries
- modifying existing systems
- collaborating
- publishing experiments openly

This is encouraged, but **give credit**.

When you use a library, substantial code, media, an idea from another project, help from another person, or meaningful assistance from an AI system, make that contribution visible in your documentation.

A useful historical reference for the course's approach to attribution and creative coding is:

- [Golan Levin's Academic Integrity guidance for Creative Coding](https://courses.ideate.cmu.edu/60-212/f2020/syllabus/academic-integrity/)

The goal is not to pretend that creative work happens in isolation. The goal is to understand what you borrowed, what you changed, what you learned, and what decisions became your own.
